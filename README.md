# MatinOS — Portfolio of Matin Zarifamin, Senior Frontend Engineer

A personal portfolio built as a tiny operating system: a draggable widget
desktop, a macOS-style dock where every shipped project is an app, and a
**real, working terminal** — click it and type `help`.

## Highlights

- **Interactive terminal** — `whoami`, `projects`, `open seltrip`,
  `contact`, `sudo` … the command engine is pure TypeScript
  ([src/lib/terminal.ts](src/lib/terminal.ts)) and fully unit-tested.
- **OS desktop metaphor** — boot splash (once per session), glass menu bar,
  bento widget grid you can rearrange by dragging the grip, and a dock with
  genuine magnification physics.
- **Bilingual** — English & Persian with full RTL, Jalali calendar, and
  Persian digits. Locale routing happens in [src/proxy.ts](src/proxy.ts)
  driven by `Accept-Language`.
- **Light/dark wallpapers**, `prefers-reduced-motion` respected, keyboard
  focus visible, semantic dialog/tooltip roles.

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS 4
· Framer Motion · react-grid-layout · Vitest + Testing Library

## Commands

```bash
npm run dev        # develop on http://localhost:3000
npm run build      # production build
npm start          # serve the build
npm test           # run the vitest suite
npm run lint       # eslint
npm run typecheck  # tsc --noEmit
```

## Structure

```
src/
  app/[lang]/        # localized layout + page, SEO metadata, robots/sitemap
  components/
    desktop/         # menu bar, dock, widgets, windows, boot screen
    shared/          # modal, toggles, icons
  data/              # profile facts + project registry (language-free)
  i18n/              # locale config, dictionaries (en/fa), provider
  lib/               # terminal engine, datetime, cn
```

## The domain, and deploying

One name, one place: `NEXT_PUBLIC_SITE_URL`. Canonical URLs, `hreflang`,
OpenGraph images, `robots.txt`, `sitemap.xml`, the JSON-LD and the contact
line printed on the résumé PDF all derive from it.

`next.config.ts` resolves it in this order, so a fresh Vercel deploy is
correct before any domain exists:

1. `NEXT_PUBLIC_SITE_URL`, if set
2. `VERCEL_PROJECT_PRODUCTION_URL` — the deployment's production host, which
   Vercel also sets on previews, so a preview's canonicals point at production
3. `https://matinzarifamin.vercel.app`, the address that is live today

### On Vercel

Deployed at **https://matinzarifamin.vercel.app** — imported from this repo, no
environment variable set, because step 2 above already resolves to that host.

Once matinzarifamin.ir is bought: add the domain in Vercel, then set

```
NEXT_PUBLIC_SITE_URL = https://matinzarifamin.ir
```

redeploy, and regenerate the PDF (below) so its contact line agrees.

### The résumé PDF

`public/matin-zarifamin-senior-frontend-engineer.pdf` is printed from the live `/en/resume` page by a
headless Chrome, which Vercel does not have — so it is committed, and has to
be regenerated by hand whenever the domain or the résumé content changes:

```bash
NEXT_PUBLIC_SITE_URL=https://matinzarifamin.vercel.app npm run build && npm start
npm run resume:pdf     # in a second shell
```

`npm run build` warns if the committed PDF does not mention the configured
domain, so a forgotten regeneration shows up in the Vercel build log.

Copy `.env.example` to `.env.local` to set the domain for local development.
